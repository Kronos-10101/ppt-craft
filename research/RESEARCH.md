### Key takeaways for the new skill
- **No existing skill does GitHub-URL + emphasis-notes → faithful general-purpose PPTX.** That is the open gap.
- **Code-grounded truthfulness is the hard lesson**: the SmartLease repo→deck pipeline produced 17 FALSE out of 40 audited claims (NPU execution, on-device models contradicted by code). Standing rule for the new skill: **code wins over README/docs**; every claim needs a provenance chain (slide-maker's `Sources:` pattern + asrayg's evidence ledger).
- **Architecture to emulate**: siril9's source-first pipeline (fix source and rebuild, never patch the generated PPTX) + anthropics' corruption-footgun list + mandatory render QA (LibreOffice headless → PDF → image review).
- **License posture**: build original content. MIT-compatible references (siril9, adewale, pitchkit, asrayg) are fine for ideas; do NOT lift text/scripts from the proprietary anthropics skill or AGPL guizang.
- **Alternative technical paths** (document as options, not core): Marp (`marp deck.md --pptx`, git-friendly Markdown), Slidev (dev talks; PPTX export community-supported), Pandoc `--reference-doc=brand.pptx` (designer template + Markdown content — underused), HTML→PDF→PPTX (max fidelity, lossy editability), pptxgenjs (Node-first, granular shapes, own footguns).

### python-pptx — consolidated capability/limit sheet (verified against official docs + field reports)
**Can do:** create/read/update .pptx with no PowerPoint installed; round-trip any OOXML (all elements preserved); slides from layouts; text with run-level formatting; images at arbitrary position/size; tables; autoshapes + connectors + freeform builder + group shapes; native editable charts (column/bar/line/pie + XY-scatter/bubble, "most chart types other than 3D", embedded workbooks); notes slides; hyperlinks; core properties; theme/layout/master access.
**Hard limits:** NO rendering engine (cannot preview; QA needs LibreOffice/PowerPoint); NO PPTX→PDF/image conversion; NO SmartArt creation (round-trips only); NO multi-plot/combo chart creation (reads existing); NO slide duplication or cross-presentation copy (only `add_slide(layout)`); `text_frame.text = ...` collapses formatting to one unstyled run (must assign `run.text`); `add_picture` raises on SVG/EMF; NO animation/transition API; NO equation/OMML API (workaround: LaTeX→OMML injection or pre-rendered images); gradients linear-only; legacy .ppt unsupported; **template-first workflow is the designed pattern** (designer builds masters/layouts once; agent fills placeholders).
**Maintenance flag (unverified):** third-party research claims no releases since Aug 2024; python-pptx-ng fork exists (group shapes, freeform, video, pattern fills). Verify on PyPI before the skill repeats either claim.

## B. Seven type dossiers

### Dossier 1 — Business case study presentations (incl. Indian case competitions)

**Purpose:** recommend a course of action on a business problem, defended before a jury; in India, case comps double as recruitment pipelines.
**Canonical structure (slide-by-slide):** CBS toolkit 5-part — 1) Executive summary / set the stage, SCQA, recommendation up front (1–2 slides); 2) Key insights driving to the recommendation (2–4); 3) Solution detail, "the body" (2–5); 4) Impact, risk, implementation (3–4); 5) Summary + call to action (1). Indian winner's arc: Problem Statement + scope → Research (fieldwork evidence) → Top-3 Insights → Ideas (often 4Ps, wireframes) → Feasibility (technical/financial/operational — "critical") → Finance & Timeline. Band: **10–15 slides, 10–20 min + 5–10 min Q&A** (ITC: 10-slide cap; Brandstorm: 10 slides, 16:9, PDF; War Room campus: 20+10).
**Observed in the wild (Track C, 6 real decks):** GCCH M&A submissions run **38–106 slides** (25–40% appendix + 7–12 bibliography slides); assertion headlines dominant, often two-line (topic + assertion, e.g. "An acquisition of Vestas would be dilutive to Siemens"); median **180–307 words/slide** — very dense; **zero native PPTX charts** (all visuals pasted images; 552 images in one deck); zero speaker notes. **Divergence flags:** recommendation stated TWICE (exec summary + conclusion); financials presented BEFORE the recommendation as evidence; no standalone implementation section in 3/4 decks; "alternatives" = alternate acquisition target with full mini-valuation; Table of Abbreviations in all 4 (absent from canon); industry analysis 8–12 slides.
**Design conventions:** action titles (complete-sentence takeaways, 7±2 words; title-only read-through must reconstruct the argument); pyramid/SCQA; one slide = one message; sourced exhibits (one chart/table per slide); appendix discipline; 2–3 colors, consistent formatting.
**Common mistakes:** buried meaning/text-heavy slides; skipping the feasibility/finance spine; rigid framework application (5 Forces/SWOT as answer, not tool); losing the prompt; unsupported exhibits; presentation-day failures (unreadable mini-diagrams, no rehearsed Q&A).
**Indian landscape (verified):** HUL L.I.M.E. (#1 prestige, Dare2Compete 2019; one-pager-per-category template with hard word limits 30/75/100 words; ~12 top B-schools); ITC Interrobang (10 slides, "no pre-determined structure", **originality/creativity highest-weighted criterion**, PPI + ₹1,00,000); L'Oréal Brandstorm (global since 1992; 10 slides max, 16:9 PDF, 5+5 world finals; winners recruited); Mahindra War Room (2009–~2024) → **rebranded as Mahindra Rise Challenge (Forbes India)**; The Ken's Case Competition (newer). Sourced India-vs-global differences: sponsor-proprietary formats replace Minto structures; creativity outranks analysis rigor (vs generic rubrics); written deck filters before any live pitch (must be self-explanatory — closer to MBB document decks).
**Key sources:** CBS Case Competition Toolkit (scribd); ITC Interrobang S14 brochure (scribd) + itcportal.com/careers/itc-interrobang.html; HUL LIME guidelines (scribd/slideshare); Brandstorm 2019 rules (ubu.es); Forbes India (War Room→Rise); unstop.com awards 2019; Minto Pyramid Principle summaries; efinancialmodels case-deck guide.

### Dossier 2 — Academic / class presentations

**Purpose:** coursework seminars, project presentations, classroom teaching decks (student talk vs instructor lecture = different genres).
**Canonical structure:** Title (name/course/guide) → Motivation FIRST (Hagen: mandatory, even before agenda) → Agenda (omit for 10–15 min talks) → Objectives → Background (minimal) → Literature review (gaps, not dumps) → Methodology (key procedures + why) → Results (2–3 key figures) → Discussion/Limitations → Conclusion + future work → References → **Summary slide, never a bare "Thank you"** (Hagen: "completely useless") → Q&A. Budget: ~1 min/slide; UNE 5–6 slides/10 min; York 7–8/12 min. Teaching decks differ: slides are cues, not the lecture; signpost/chunk; label exam-essential vs non-essential; can carry more text as study aids.
**Observed in the wild (Track C, 3 real class decks):** **11–13 slides**, tightly clustered; almost entirely **topic labels** ("Data Preprocessing", "Classification – Decision Tree") — zero assertion headlines; very sparse text (median 1–44 words/slide; one deck's content entirely image-embedded); zero native charts; images carry figures; one deck has notes on 13/13 slides (real content in notes). **Divergence flags:** no references/bibliography in ANY class deck; no formal motivation slide; results compressed; "Ethical Considerations"/"Practical Recommendations" appear as course-rubric artifacts.
**Design conventions:** Duarte (slide:ology): one idea/slide, headline = takeaway, visuals support never decorate, minimal text, whitespace, meaningful contrast; *resonate*: oscillate "what is" vs "what could be". Alley assertion-evidence model (most evidence-backed): sentence-assertion headline ≤2 lines, 28pt bold sans, visual evidence instead of bullets, ≤~20 words, 2–4 item lists max, ½-inch whitespace under headline. Typography: titles 38–48pt (APSU), body ≥24pt; ≤6 lines/slide, 7 words/line; ~3 colors; cite everything borrowed (short-form on slide, full list at end); accessibility (contrast, alt-text, reading order).
**Common mistakes:** text walls (#1); reading slides aloud (audience "listening to two people at once"); revealing everything at once; visual chaos; decoration/distraction; slides doing the speaker's job; no story; bare "Thank you" ending.
**India notes (sourced):** Raut & Gupta (Maharashtra medical college): 51.6% students prefer chalk-and-board, 78.7% teachers prefer PPT; students can't match note-taking pace to slide changes. Shinde & Patil (2015): student verbatim — "professors just read the stuff from their slides without elaborating"; recommendation: PPT for pictures/videos only. VTU-pattern: **4 mandatory PowerPoint seminars as graded deliverables** (hard+soft copy submitted) — the PPT is an institutional artifact, not just a talk aid. The Hindu (2014): 24–44pt, 6 lines max — matches global norms. No pan-India text-density study found; no AICTE/UGC slide standard found.
**Key sources:** UCLA/APSU/Valdosta/Hagen/York/UNE/UW/SLU teaching guides; NSCC assertion-evidence; Duarte summaries; Raut & Gupta (ijcbr.com); Shinde & Patil (languageinindia.com); VTU seminar guidelines (scribd); The Hindu "Present it right" (2014).

### Dossier 3 — Marketing & sales decks

**Purpose:** marketing decks = demand-gen/awareness (high-level, persuasive); sales decks = deal-closing conversation tools (deeper, consultative, reconfigurable mid-meeting).
**Canonical structure (sales):** Cover → Problem (buyer's pain) → Solution → Key Features (3 hero) → How It Works (3-step) → Social Proof → Expected Results/ROI → Pricing → Why Us vs Alternatives → Onboarding → Team/About → Next Steps/CTA (12-slide canonical; enterprise 15–20 with cost-of-inaction, security, timeline, appendix). The Zuora archetype (Raskin, most-cited): open with undeniable world-shift (not problem — problem-first puts prospects defensive) → stakes → product as "Magic Gifts" to the "Promised Land" → evidence framed in that context. Marketing-vs-sales differences verified: goal/audience, depth vs breadth, fixed-linear vs buyer-journey structure, minimal vs product-led visuals, traction vs case-study proof, aspirational vs consultative tone.
**Observed in the wild (Track C):** HONEST GAP — zero real company sales decks available as .pptx (all login-walled/PDF). Gallery templates (flattened) show: sales decks track the canonical arc closely (best canonical fit in the study); assertion-dominant titles ("From Friction to Forward Motion", "Proof in Practice"); ~20–40 words/slide; BUT the "marketing" template was an internal planning deck (objectives→audience→journey→positioning→competition→funnel→channels→calendar→measurement) — **no pricing, no CTA**: "sales deck" ≠ "marketing plan deck". Risk/objection slides ("Questions We Can Resolve") are a structural feature the canon doesn't name. LF's professional template encodes design systems, not narrative.
**Design conventions:** one idea/slide, 6–8 lines max ("billboard clarity"); visual hierarchy (headline = point, subhead = context, proof = evidence); 3-second test; product-led visuals ("if you say it, show it"); proof blocks (logo bars, testimonials, before/after); value-prop formula ("We help [audience] achieve [result] through [method]"); 2–3 brand colors, one icon style; dual-mode design (light live version + detailed appendix/notes for send-ahead); metrics headlined as takeaways ("Increased conversion 32% in 60 days").
**Common mistakes:** the "slideument"; feature-dumping; no visual hierarchy; weak/absent proof; company-first openings; unclear core message; one-size-fits-all; no objection handling; logo soup; overdesign.
**India notes (sourced):** "Death by PowerPoint" as documented Indian corporate phenomenon (ET 2010: 78-slide deck for a one-hour meeting, performance theater); "Sanjeevani decks" (TOI 2026: 50 slides for 15 min, "in the interest of time, let's skip this slide", Rorschach-test font sizes); teleprompter usage (Bhaduri 2013); full-sentence slides read verbatim (bhatnaturally 2008); Entrepreneur India (2025): benefits-first, customize per buyer, before/after framing; Deasra (2026): **WhatsApp/email pitches must be short, scannable, one clear next step** — WhatsApp is a first-class Indian sales channel. No quantitative India-vs-global norms found.
**Key sources:** Raskin "Greatest Sales Deck" (medium.com); mrrunlocked.com sales-deck template; contentbeta.com + FasterCapital (marketing vs sales); scayver sales-enablement SKILL.md; Pitchworx/Marka Works/jamesdavid design teardowns; ET/TOI/Bhaduri/bhatnaturally (India); Entrepreneur India; Deasra.

### Dossier 4 — Investor / startup pitch decks

**Purpose:** raise capital; most decks now read via link without the founder present (self-explanatory = mandatory).
**Canonical structure (reconciled):** Sequoia's "Writing a Business Plan" (15–20 slides): Company purpose (one declarative sentence) → Problem → Solution ("eureka moment") → **Why now** → Market (TAM top-down, SAM bottom-up) → Competition/alternatives → Product → Business model → Team → Financials (P&L, cash flow, cap table, **the deal**). Kawasaki 10/20/30 (2006, still cited): 10 slides, 20 minutes, ≥30pt font — treat as psychological filter, not formatting law (cramming 40 slides into 10 is a documented failure). YC seed (10–12): title, problem, solution, market, traction, team, ask; **lead with whatever is strongest**; non-obvious-insight slide; dated specific traction (never smoothed hockey sticks); team = founders not advisors; ask = amount + what it buys. **Reconciliation:** shared spine Problem→Solution→Market→Model→Competition→Team; target **10–12 core slides + appendix, hard ceiling ~20** (DocSend: successful seed decks avg 19.2 pages, engagement drops after 20); Team placement disputed (Sequoia puts it 9th; YC/DocSend-data argue early — Team is #2 most-viewed section); Financials in only 58% of successful seed decks but most-viewed when present; Why-now skipped by ~75% yet is a Sequoia signature.
**Observed in the wild (Track C, 4 decks):** real decks run **7–10 slides** (shorter than canon); DermoAI: 4/7 slides = feature walkthrough, NO market/team/ask/financials; mixed title phrasing (labels + assertions + imperatives); median 66–71 words/slide; image-heavy, zero charts; famous decks (Airbnb/Uber) are PDF-only — **no famous .pptx obtainable**. **Divergence flags:** real early-stage decks are product-demo-heavy and skip the financial machinery the canon prescribes.
**Design conventions:** one idea/slide (retain 1–2 of 5–7 key ideas); legible (30pt+, simple typeface, dark on white); declarative not cute; one point per graphic; line graphs for growth; bottom-up TAM; stranger-must-understand-at-a-glance. DocSend data: avg 3:44 view time; Team in 100% of successful decks; 12% mobile views.
**Common mistakes:** too long/crammed; burying the strongest card (Team at end; skipping Why-now); feature-list opening sentence; deal terms in the deck; "we have no competitors"; vanity top-down TAMs; detailed seed financials; bloat (Indian investor blacklist per YourStory: motivational quotes, celebrity name-drops, advisor lists, tech-stack deep dives, valuation/exit/M&A plans); typos; fake traction (undated hockey sticks, MoUs-as-traction).
**India notes (sourced):** NO structural difference found — Indian VCs teach the same template (Sequoia India/Peak XV: Kemps' "Anatomy of a pitch" masterclass; Anandan on founder quality; ~70% of Surge companies build global from day one). What differs: the **metric bar** — MRR/ARR, gross margin, cohort retention, CAC payback, burn multiple; vanity metrics (downloads, GMV, MoUs) "carry little weight" (LegalSuvidha 2026); no valuation in outbound deck (Rule 11UA working when asked). Indian formats: ISFM 2026 (Problem→Solution→Market→Model→GTM→Traction→Competition→Team→Financials→Ask + 3-min video); IIT Bombay Eureka! (rigorous unit economics, "use of funds" slide often decisive); UP-govt 12-section rules. The user's "not common in India" observation is **not supported at VC level** — every Indian VC source teaches the global format; the gap, if any, is at student/competition-deck level (38-slide average pitches).
**Key sources:** Sequoia "Writing a Business Plan" (sequoiacap.com/article/writing-a-business-plan; verified via faithful reproductions); Kawasaki "The Art of the Pitch" (guykawasaki.com); YC library (seed/Series A/design guides); DocSend fundraising research; YourStory investor survey; LegalSuvidha 2026 guide; ISFM 2026; Eureka! writeup; startupfundraising.com teardowns.

### Dossier 5 — Consulting / strategy decks

**Purpose:** drive executive decisions; the deck must survive as a read-alone document.
**Canonical structure & page conventions:** Minto's Pyramid Principle (verified across independent summaries): **answer first, top-down**; every idea summarizes the level below; same-kind groupings; logical order (time/structure/importance); **SCQA** introductions; **MECE** (mutually exclusive, collectively exhaustive — tests inductive groupings, not deductive chains); deduction vs induction (prefer induction at the key line); "exactly three reasons" is NOT a Minto rule. Page level: **action titles** — complete-sentence takeaways, never topic labels; **title-only read-through must reconstruct the argument** (use as QA); one message per slide; horizontal flow (titles in sequence = argument) + vertical flow (title summarizes body); slide anatomy (action title → framing subtitles → exhibit → footer with source/units/date/page); **ghost/skeleton deck workflow** (5–20 bullet titles aligned with partner BEFORE building); executive summary upfront (SCR, stands alone); **appendix discipline** (15 tight slides > 60-slide dump; pre-empt the skeptic); exhibit discipline (chart matched to message, strip chartjunk, direct labels, color-the-insight, source line + units on every exhibit). Standard arc: exec summary → context/problem → key findings → recommendations → implementation/roadmap → appendix. QA rituals: "so what?" per slide; number audit.
**Observed in the wild (Track C):** HONEST PROVENANCE WALL — no authentic MBB deck freely downloadable (.pptx). Best artifact: alanjiao1988/consultant-deck's python-pptx-generated 8-slide demo — **best canonical match** (quantified assertion headlines, sourced exhibits, explicit recommendation boxes, source lines; densest text in study, median 45 w/slide; table/chart pole: 4 dense tables + 2 native charts, 0 images). Gallery "consulting" decks are **workshop facilitation decks**, not MECE analysis decks ("consulting" in template-land = facilitation aesthetics). **Divergence flags:** NO appendix in any observed deck (canon overstates appendix discipline in practice samples); pyramid holds in the repo artifact, not in templates.
**Design conventions:** restrained not decorative (white bg, navy emphasis, 1–2 fonts, one body size); color = insight emphasis only; footer chrome (sources, units, page, date; "Preliminary/For Discussion" stickers); confidentiality markings + oral-presentation disclaimer.
**Common mistakes:** copying the look not the reasoning; topic titles; multiple messages/slide; building before the storyline; descriptive-not-insightful output; decorative frameworks (invented probabilities, false precision); missing dissent/ownership; formatting sloppiness (partners catch it fast); slides-as-teleprompters.
**Authenticity flags (important for the skill):** "McKinsey Presentation Handbook" PDFs on SEO-spam domains = NO evidence of genuineness; most online "McKinsey decks" unverifiable (honest ones disclaim affiliation); Scribd 2002 template looks like a real artifact but unverified; all ex-consultant credentials self-declared. The skill must source Minto + practitioner consensus, never fake firm authority.
**India notes (sourced, editorial):** "Sanjeevani decks" (TOI 2026: 50 slides/15 min, 90+ word slides read verbatim); one-deck-four-jobs (present + email + document + impress boss + survive legal → tiny fonts, paragraphs); "open PowerPoint first, think later" (bhatnaturally 2008); presentation-dominated culture (ET); text-saturated public-sector decks (ummid 2018). Directionally supports the user's observation; **no formal study exists** — do not bake into the skill as fact without human verification.
**Key sources:** Minto summaries (GitHub mod482, befreed.ai, slideshare); PrepLounge; visualsculptors.com; Analyst Academy BCG breakdown; mycelhq executive-deck-storylining; TOI/Economic Times/bhatnaturally/ummid (India); python-pptx docs (charts, SmartArt).

### Dossier 6 — Research thesis / defense presentations

**Purpose:** defend a contribution claim under examiner challenge ("a defence is a judgement test, not a memory test" — Tsekleves, 45+ theses examined).
**Canonical structure (IMRaD mapped to talk):** Title → Outline → Introduction + problem (2–3) → Research questions → Literature review/gap (2–3, not a dump) → Methodology (2–3, **+ why this design fits**) → Results, the bulk (~8+, one finding/slide, figure-led) → Discussion → Limitations (proactive) → Contributions/novelty (specific) → Future work → References/Acknowledgments → Thank-you/Q&A → **Backup slides** (hidden appendix). Advice: **story, not IMRaD read-aloud**; open with RQ + key finding in two sentences (Tsekleves). Time: ~1 slide/min cap; 20–30 slides typical; masters defenses often 20 min + 10 Q&A.
**Observed in the wild (Track C, 2 real defenses — CMU PhD 91 slides, MS 44):** shared skeleton: title → **motivation BEFORE outline** (outline at slide 11/91 in one) → background block → **outline repeated before every chapter** → per-chapter IMRaD with **mini-conclusions per chapter** → future work → acknowledgments → "Questions?" → **formally sectioned backups** ("Extra Slides", "Old Slides") → references near end. Topic-label + question titles ("What is graphene?", "Is this model accurate?"); median **13–23 words/slide** (figures carry content); zero native charts (images); notes carry near-transcripts (31–75% of slides). **Divergence flags:** repeated outlines (canon says once); per-chapter conclusions (canon says one); motivation-before-outline; sectioned backups; notes-driven delivery unacknowledged by canon.
**Defense norms & Q&A discipline:** ten canonical "why" questions (problem, RQ, lit boundary, method, sample, framework, significance, contribution, limitations, degree-worthiness); examiner pattern (broad → chapter-by-chapter → deliberate challenges → wrap-up); prep 6–8 weeks; hot-seat binder/defense map; research examiners' areas; backup slides = studying; restate-then-answer; "I don't know, here's how I'd find out" > bluffing; never change core argument under pressure; limitations taxonomy (contained/methodological/structural); mock defenses; logistics (timed rehearsals, venue equipment test, cloud+USB+PDF backups).
**Design conventions:** assertion-evidence architecture; evidence-forward figures (simplified for projection, aspect ratios preserved); body ≥24pt, headers ≥28–32pt, figure labels 18–24pt; high contrast, color-blind-safe; tables minimal; progressive reveal; **equations via LaTeX/PPTX equation editor — never ASCII**; author–year inline citations.
**India notes (sourced — UGC 2022 Regulations, Gazette of India):** **Clause 11(2): mandatory pre-submission presentation** before the Research Advisory Committee, open to all faculty/scholars; **Clause 11(5): supervisor + ≥2 external examiners** (one preferably from outside India); viva-voce board, may be online, **open**; viva only if both externals recommend acceptance; **publication mandate REMOVED** (was: 1 journal paper + 2 conference presentations) — but universities vary (Yenepoya/Krishna U kept stricter rules). Distinctive Indian formal features: **two-stage public process** (pre-submission seminar + final open viva), synopsis approval stage, **45-minute presentation norms** (MGMIHS, university annexures), **explicit PPT requirements** (Krishna University 2024 draft), examiner reports structuring the viva, corrections-certification workflow. **Design-culture differences NOT verified** — no source on Indian vs global viva deck formats.
**Key sources:** presenti.ai/aippt.com/SciSpace defense guides; Tsekleves examiner posts (LinkedIn); GradCoach viva guide; Inside Higher Ed; abhinavbwj AEC scholar SKILL.md; psaunderualberta make-presentation SKILL.md; UGC 2022 Gazette (old.rvu.edu.in); The Hindu explainer; VTU final-viva format; IIITD/MGMIHS/Yenepoya/Krishna University regs; spyrosmouselinos phd-thesis CLAUDE.md (real 20-slide/30-min spec).

### Dossier 7 — Hackathon decks (3 subtypes)

**Subtype 1 — Demo-day judging pitch.** Canonical: 5-slide minimal (3-min: title → problem → solution → demo → architecture+roadmap) and 8–9 slide expanded (3–5 min: hook/problem → one-sentence solution → **live demo 60–120s, the largest block** → how-it-works → tech stack → impact → business case → team → vision). Rules: max 6 slides for 3-min; backup video mandatory ("if the demo dies, play the video, do not apologize"); scripted beats; speaker notes carry the script. **MLH official rubric = Technology, Design, Completion, Learning** (equally weighted; explicitly NOT code quality, pitching skill, or idea quality — the "technology/originality/practicality" mashup is inaccurate shorthand). Variants: ETHGlobal (Technicality/Originality/Practicality/Usability/WOW), Hack the North, Devpost sets. Design: one visual + ≤8 words/slide; judges decide in ~30s. Mistakes: too much coverage, overloaded slides, pitch longer than demo, no backup, vague framing, weak ending. **Observed (Track C, 5 decks):** 6–10 slides; topic labels in student decks, assertions in stronger ones ("Why Conservative Design Wins"); median 66 w/slide; demos live **off-slide** (no real demo slides); zero speaker notes in student decks; "challenges" appears more than canon suggests.
**Subtype 2 — SIH idea-submission deck (India).** **Official fixed 6-slide template** (verified: https://www.sih.gov.in/letters/SIH2025-IDEA-Presentation-Format.pptx; corroborated by 4+ mirrors, 2024/2025/2026 editions identical): 1) Title page (PS ID, title, theme, category, team ID/name); 2) Idea title/proposed solution (+ innovation & uniqueness); 3) Technical approach; 4) Feasibility and viability; 5) Impact and benefits; 6) Research and references. Rules: max 6 slides, **no paragraphs** (points/diagrams only), **PDF upload only**, delete the pointers slide. Evaluation: novelty, complexity, clarity, feasibility, practicability, sustainability, impact, UX, future-work potential. Workflow: internal college hackathon → portal submission (SIH 2026: Aug 21–Sep 20) → national evaluation → training → grand finale (Dec 2026); SIH 2026 Phase 2 adds narrated demo video (explicitly not AI-generated) + GitHub repo. **Differs from demo-day:** no live pitch — evaluated by *reading*; fixed template (creativity in content, not layout); research depth rewarded (lit review, competitor comparison, cost estimation). **Observed (Track C, 4 SIH decks):** 6-slide cap CONFIRMED in 2024/2025 winner decks; pure topic labels; median 49 w/slide; diagram-heavy (11–24 images); BUT 2020/2022 **finale** decks ignore the template (10–11 slides) — skill must distinguish idea-stage vs finale-stage; observed slides denser than the template's "points not paragraphs" implies.
**Subtype 3 — Sponsor-prize/track pitch.** Tailoring playbook: architect around 2–3 sponsor techs (each doing real work); integration must live in the demo path ("show me where you use it"); "best use of X" ≠ wrapper (rubrics now name this); pitch line "We use <API> to <real job>"; name/thank the sponsor; read prize criteria as a literal checklist; Devpost "Built with" tags; metrics + feedback ("reduced response time 300ms"); track framing ("This is [track definition] for [niche]"). **Observed (Track C):** only n=1 strong sample (SmartLease iQOO 2026: 17 slides, rubric-mapped, timed speaker notes, "WORKING MVP, HONESTLY" anti-overclaim culture) + 3 partial (sponsor-judged main-track); sponsor-prize winners post code+videos, not decks — **do not overgeneralize**; empty finals-deck shell proves finals ≠ pitch decks.

## C. India-vs-global format notes (honest synthesis)

**What the evidence actually supports:**
1. **Corporate/classroom practice (anecdotal but convergent):** "Sanjeevani decks" (TOI 2026), 78-slide meetings (ET 2010), teleprompter culture (Bhaduri 2013, bhatnaturally 2008), text-saturated public-sector decks (ummid 2018) — all point the same direction: dense, text-heavy, structure-poor decks as common Indian corporate habit. This **directionally supports** the user's observation. BUT every datapoint is editorial/anecdotal; **no quantitative study exists**. Do not present as measured fact.
2. **Institutional formats that genuinely differ:** HUL LIME's word-limited one-pager template; ITC's creativity-first weighting; SIH's fixed 6-slide template; UGC's two-stage public viva + 45-min norms + explicit PPT mandates; VTU's graded seminar deliverables. These are structural India-specifics the skill should encode as modules, not footnotes.
3. **Where the user's observation does NOT hold:** Indian VC/startup pitching teaches the identical global format (Sequoia India/Peak XV, YourStory survey, ISFM, Eureka!). No India-specific pitch structure found. The gap is at student/corporate/classroom level, not institutional-VC level.
4. **Channel specificity:** WhatsApp as a first-class Indian sales channel (Deasra) — short, scannable, one-CTA pitch assets; worth a skill note.

**What could NOT be verified:** any measured India-vs-global text-density or slide-count norms; whether Indian viva/class decks differ in design culture from global ones; current 2026-season rulebooks for some comps; Tata/Deloitte case competitions (Tata Crucible is a quiz, not a case comp — unverified either way).
