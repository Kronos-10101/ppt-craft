# Hackathon decks (2026-10-09)

Three subtypes, kept distinct. Subtype 1 and 3 are live-pitch genres; Subtype 2 (SIH idea
submission) is evaluated by READING and uses a fixed template.

---

## Subtype 1 — Demo-day judging pitch

The live 3–5 minute pitch delivered to judges at demo day.

### Canonical slide arcs

- [ ] 3-min slot: 5-slide minimal — title → problem → solution → demo → architecture+roadmap.
- [ ] 3–5 min slot: 8–9 slide expanded — hook/problem → one-sentence solution → LIVE DEMO
      (60–120s, the largest time block) → how-it-works → tech stack → impact → business
      case → team → vision.
- [ ] Max 6 slides for a 3-min slot.

### Rules of engagement

- [ ] Backup video MANDATORY: if the demo dies, play the video, do not apologize.
- [ ] Beats scripted in advance; speaker notes carry the script.
- [ ] MLH official rubric = Technology, Design, Completion, Learning, equally weighted.
      Explicitly NOT code quality, pitching skill, or idea quality — the
      "technology/originality/practicality" mashup is inaccurate shorthand; correct it.
- [ ] Know the venue's rubric variant before building: ETHGlobal
      (Technicality/Originality/Practicality/Usability/WOW), Hack the North, Devpost sets.
- [ ] One visual + ≤8 words per slide; judges decide in ~30s.

### Common mistakes

- [ ] Too much coverage; overloaded slides; pitch longer than the demo itself.
- [ ] No backup video; vague framing; weak ending.

### FIELD NOTES (Track C, 5 real decks parsed, 2026-10-09)

- [ ] Observed range 6–10 slides; median 66 words/slide.
- [ ] Topic labels in student decks, assertions in stronger ones
      ("Why Conservative Design Wins").
- [ ] Demos live OFF-slide — no real demo slides observed.
- [ ] Zero speaker notes in student decks; "challenges" appears more than canon suggests.

**Sources:** MLH standard hackathon rules (github.com/MLH/mlh-policies);
juliusbrussee hackathon judging criteria; fabrizioiacuzio pitch-prep;
dharmik2510 hackathon-presentation SKILL.md.

## Subtype 2 — SIH idea-submission deck (India)

The official fixed 6-slide template — verified at
https://www.sih.gov.in/letters/SIH2025-IDEA-Presentation-Format.pptx (2026-10-09),
corroborated by 4+ mirrors; 2024/2025/2026 editions identical.

### The six slides (fixed)

1. [ ] Title page: PS ID, title, theme, category, team ID/name.
2. [ ] Idea title / proposed solution (+ innovation & uniqueness).
3. [ ] Technical approach.
4. [ ] Feasibility and viability.
5. [ ] Impact and benefits.
6. [ ] Research and references.

### Submission rules

- [ ] Max 6 slides; NO paragraphs — points/diagrams only.
- [ ] PDF upload only.
- [ ] Delete the pointers slide before submitting.

### Evaluation criteria

- [ ] Novelty, complexity, clarity, feasibility, practicability, sustainability, impact,
      UX, future-work potential.

### Workflow

- [ ] Internal college hackathon → portal submission → national evaluation → training →
      grand finale.
- [ ] SIH 2026 portal window: Aug 21–Sep 20; grand finale Dec 2026.
- [ ] SIH 2026 Phase 2 adds: narrated demo video (explicitly not AI-generated) + GitHub repo.

### How it differs from demo-day

- [ ] No live pitch — evaluated by READING.
- [ ] Fixed template: creativity goes into content, not layout.
- [ ] Research depth rewarded: lit review, competitor comparison, cost estimation.

### FLAG

- [ ] The 2025 template is the baseline: RE-VERIFY the 2026 template live before
      hardcoding it into tooling.

### FIELD NOTES (Track C, 4 SIH decks parsed, 2026-10-09)

- [ ] 6-slide cap CONFIRMED in 2024/2025 winner decks.
- [ ] Pure topic labels; median 49 words/slide; diagram-heavy (11–24 images).
- [ ] 2020/2022 FINALE decks ignore the template (10–11 slides) — the skill must
      distinguish idea-stage vs finale-stage decks.
- [ ] Observed slides denser than the template's "points not paragraphs" implies.

**Sources:** SIH official template + SPOC guidelines (sih.gov.in/letters);
zaidsayyed.in SIH 2026 playbook; joysonbeera sih-winning-presentations (GitHub).

## Subtype 3 — Sponsor-prize / track pitch

The tailoring playbook for winning "best use of X" sponsor prizes.

### Tailoring checklist

- [ ] Architect around 2–3 sponsor techs, each doing real work.
- [ ] Integration must live in the demo path — the rubric asks "show me where you use it".
- [ ] "Best use of X" ≠ wrapper; rubrics now name this explicitly.
- [ ] Pitch line on the slide: "We use <API> to <real job>".
- [ ] Name and thank the sponsor.
- [ ] Read prize criteria as a literal checklist; score yourself against each item.
- [ ] Devpost "Built with" tags filled in.
- [ ] Metrics + feedback: "reduced response time 300ms".
- [ ] Track framing: "This is [track definition] for [niche]".

### FIELD NOTES (Track C, 2026-10-09 — honesty label: small sample)

- [ ] Only n=1 strong sample: SmartLease iQOO 2026 — 17 slides, rubric-mapped, timed
      speaker notes, "WORKING MVP, HONESTLY" anti-overclaim culture.
- [ ] Plus 3 partial (sponsor-judged main-track) samples.
- [ ] Sponsor-prize winners post code+videos, not decks — do NOT overgeneralize.
- [ ] Empty finals-deck shell proves finals ≠ pitch decks.

**Sources:** asrayg sponsor-matchmaker; Devpost prize-set conventions.
