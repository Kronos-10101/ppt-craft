# Consulting / strategy decks — build checklist

Purpose: drive an executive decision. The deck must survive as a read-alone document; a reader who never attends the meeting must reach the recommendation and its reasoning from the file alone. Checked 2026-10-09 against RESEARCH.md Dossier 5 (consulting).

## 1. Storyline: Minto's Pyramid Principle

The structure, not the styling, is what makes a deck "consulting-grade."

- [ ] Answer first, top-down: the recommendation and its key reasons lead; evidence follows. Never bury the answer in the body.
- [ ] Every idea at a level summarizes the ideas one level below it; the reader can drill down or stop at any level and still have the full logic.
- [ ] Groupings contain ideas of the same kind (all actions, all problems, all findings): never mix categories in one grouping.
- [ ] Order within a grouping is logical and named: time, structure, or importance (say which one it is).
- [ ] Introductions use SCQA (Situation, Complication, Question, Answer): set the scene, name the tension, pose the question the deck answers, then answer it.
- [ ] Groupings are MECE: mutually exclusive, collectively exhaustive. Each element sits in exactly one bucket; the buckets cover the whole question.
- [ ] Apply the MECE test to inductive groupings (grouping similar observations), not to deductive chains (if-then logic follows its own rules; don't MECE it).
- [ ] At the key line, prefer induction (reasons grouped to a conclusion) over deduction (a chain of premises), because induction is what groupings audit.
- [ ] "Exactly three reasons" is NOT a Minto rule. Three is a presentation habit, not a structural requirement; use the number the logic demands.

## 2. Page level: action titles

- [ ] Every slide carries an ACTION TITLE: a complete sentence that states the takeaway, never a topic label ("Market overview" becomes "Market X is shrinking 4% annually on volume").
- [ ] TITLE-ONLY READ-THROUGH QA: read only the titles in order. If the full argument (situation, findings, recommendation) cannot be reconstructed from titles alone, the storyline is broken; fix titles before touching bodies.
- [ ] One message per slide. A second message means a second slide.
- [ ] Horizontal flow: titles read in sequence = the argument. Vertical flow: the title summarizes the body below it.
- [ ] Slide anatomy in this order: action title, framing subtitles (what the reader is looking at), exhibit (chart/table), footer (source, units, date, page number).

## 3. Ghost / skeleton deck workflow

- [ ] Before building any slide, write 5-20 bullet titles (the ghost deck): the full argument in title form.
- [ ] Align the ghost deck with the decision-maker (the partner in the dossier's workflow) and lock it: no slide construction starts until the storyline is agreed.
- [ ] Treat every edit after lock as a storyline change first, a slide change second: update the title list, then the deck.

## 4. Standard arc and executive summary

- [ ] Standard arc: executive summary, context/problem, key findings, recommendations, implementation/roadmap, appendix. Deviate only with a stated reason.
- [ ] Executive summary goes first and stands alone: SCR (Situation, Complication, Resolution) in one page; the reader gets the recommendation, the top reasons, and the ask without opening the rest.
- [ ] Recommendations name an owner, a decision needed, and a timeframe. A recommendation nobody must act on is a finding, not a recommendation.

## 5. Appendix discipline

- [ ] 15 tight appendix slides beat a 60-slide dump: the appendix is a weapon, not a filing cabinet.
- [ ] Every appendix slide answers one anticipated objection: pre-empt the skeptic, don't archive the working papers.
- [ ] Referenced, not dumped: each appendix slide is cited from the body at the point it supports.

## 6. Exhibit discipline

- [ ] Chart type matched to the message: trend = line, comparison = bar/column, composition = stacked or pie, distribution = histogram/scatter. Never pick by decoration.
- [ ] Strip chartjunk: no 3D, no gratuitous gridlines, no gradients; ink goes to the data.
- [ ] Direct labels on the data; legends are a last resort (the eye should not travel between legend and line).
- [ ] Color the insight: color highlights the one number or series the title claims; everything else recedes to gray.
- [ ] Every exhibit carries a source line and units. No source, no exhibit.

## 7. QA rituals

- [ ] "So what?" per slide: if the slide's answer is "it's interesting," the slide is not done. Rewrite the title until the implication is explicit.
- [ ] Number audit: totals tie, growth rates recompute from stated bases, shares sum to 100, units are consistent across slides; one wrong number kills the deck's authority.

## 8. Design conventions: restrained, not decorative

- [ ] White background, navy emphasis; 1-2 fonts total, one body size throughout.
- [ ] Color = insight emphasis only. If a color is not carrying meaning, it is decoration: remove it.
- [ ] Footer chrome on every page: sources, units, page number, date; working drafts carry "Preliminary" or "For Discussion" stickers.
- [ ] Confidentiality markings where the client requires them; an oral-presentation disclaimer when the deck is presented live (the deck says what was covered in discussion, not the reverse).

## 9. Common mistakes

- [ ] Copying the look, not the reasoning: navy boxes and footers around a topic-labeled, message-free deck.
- [ ] Topic titles instead of action titles.
- [ ] Multiple messages per slide.
- [ ] Building before the storyline: slides exist before the ghost deck is locked.
- [ ] Descriptive, not insightful: pages that report data without saying what it means for the decision.
- [ ] Decorative frameworks: invented probabilities, false precision, and framework-shaped scaffolding with no analytic content.
- [ ] Missing dissent and ownership: no named owner for recommendations, no acknowledgment of counterarguments.
- [ ] Slides as teleprompters: reading the deck aloud instead of using it as a document.
- [ ] Formatting sloppiness: misaligned boxes, inconsistent fonts, uncorrected typos. Partners catch this fast; it reads as carelessness about the analysis.

## 10. AUTHENTICITY WARNING

- [ ] NEVER fake firm authority. This skill does not produce "McKinsey decks," "BCG decks," or any firm's house style.
- [ ] "McKinsey Presentation Handbook" PDFs on SEO-spam domains have NO evidence of genuineness; treat them as unverified.
- [ ] Most online "McKinsey decks" are unverifiable; the honest ones disclaim any firm affiliation.
- [ ] Ex-consultant credentials attached to online decks are self-declared and unverified.
- [ ] Source Minto's published principle plus practitioner consensus only. When a claim's provenance is unclear, say so in the notes, not in the deck.

## 11. India notes (anecdotal: do NOT present as measured fact)

- [ ] Sanjeevani decks (TOI 2026): the 50-slides-in-15-minutes anti-pattern, 90+ word slides read verbatim; one-deck-four-jobs (present + email + document + impress the boss + survive legal) producing tiny fonts and paragraphs; "open PowerPoint first, think later" (bhatnaturally 2008); presentation-dominated meeting culture (ET 2010); text-saturated public-sector decks (ummid 2018).
- [ ] These datapoints are editorial/anecdotal and directionally consistent, but NO formal or quantitative study exists. Use them as anti-patterns to avoid, never as statistics in a deck.
